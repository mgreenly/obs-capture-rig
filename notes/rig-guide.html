Headline finding

4K60 is not available from any input

Neither capture device can deliver 4K at 60 fps

This is a hardware ceiling on the capture side, not an encoding limit. The M4's media engine would handle 4K60 HEVC without effort — but nothing in the chain can hand it 4K60 frames. Encoder headroom is not your constraint.

Resolved — the camera now feeds 2160p29.97

The blocker was File Format sitting on XAVC S HD, not anything in the HDMI chain. 4K Output Select was already on Memory Card+HDMI, which was correct all along; it was simply hidden until the camera was switched to Movie mode. Setting XAVC S 4K / 30p 100M with Proxy off flipped the output immediately — no cable reseat, no HDMI Resolution change needed.

A frame-rate mismatch to watch

The Cam Link runs at 59.94 fps (NTSC), while the HD60 X's 1080p mode is exactly 60.00. They are not the same clock. Set the OBS canvas to 59.94 and the camera — your hero source — stays clean; the HD60 X absorbs the 0.1% difference far more gracefully than a face does. If you record at 30, use 29.97 for the same reason.

Do this first · Sony ZV-1

Getting 4K30 out of the camera

Why "4K Output Select" is missing — the ordering trap

Sony creates a chicken-and-egg here. HDMI Settings can only be changed while the cable is unplugged. But 4K Output Select only appears while the cable is plugged into a 4K-capable device. So there is no single pass through the menu that sets both — you have to configure one, move the cable, then configure the other. Steps below are split accordingly.

It is not the HD60 X

The HD60 X sits on a separate cable entirely and never touches the camera's HDMI path. Its capability list is also static — it advertises all 14 modes, down to 720×480 SD, no matter what is plugged into it. The Cam Link is the opposite: it reports only what it is actually being fed, which is how we know your camera is sending 1080p59.94 right now.

1 · Movie mode
Press the Mode button → Movie
Most likely culprit. The ZV-1 uses a Mode button on the top plate cycling Still / Movie / S&Q — there is no mode dial. Pressing the red MOVIE record button records video but does not put the camera in Movie mode, and 4K Output Select stays hidden in Still mode. Confirm the screen shows movie framing and a movie-mode icon before going further.
2 · Region
MENU → Setup → NTSC/PAL Selector → NTSC
30p only exists in NTSC; PAL gives 25p. This restarts the camera and wants the card reformatted, so get it done early.
3 · File format
MENU → Movie tab → File Format → XAVC S 4K
The Movie tab — Sony's documentation calls it "Camera Settings2", but the camera labels it Movie1 / Movie2. Not the Quality/ImageSize tab, which is stills only. Record Setting 30p 100M sits directly below.
4 · Proxy recording
MENU → Movie tab → Proxy Recording → Off
Same Movie tab, usually a page across — use the right arrow to reach Movie2. Sony is explicit: recording 4K with proxy active means movies "will not be output to a device connected by HDMI cable." No on-screen warning — just a dead capture.

Now unplug the HDMI cable

HDMI Settings grey out while a cable is attached. Disconnect it from the camera before attempting the next three.

5 · HDMI resolution
MENU → Setup → HDMI Settings → HDMI Resolution → 2160p/1080p
Not Auto. Auto negotiates against the Cam Link's EDID and often settles on 1080p.
6 · Clean output
HDMI Settings → HDMI Info. Display → Off
Strips focus boxes and overlays from the feed.
7 · Device control
HDMI Settings → CTRL FOR HDMI → Off
Stops the camera reacting to HDMI-CEC chatter mid-take.

Plug the cable back in — camera to Cam Link, Cam Link to the Mac

The Cam Link is bus-powered and only presents its 4K EDID once the Mac has it enumerated. Both ends connected, camera on, still in Movie mode. Now the next item should exist.

8 · 4K output select
MENU → Setup → 4K Output Select → HDMI Only(30p)
Choose Memory Card+HDMI instead if you want a card backup — it costs thermal headroom and clip length, and step 4 becomes non-negotiable.
9 · Power management
Power Save Start Time → Off  ·  Auto Power OFF Temp. → High
Otherwise the camera sleeps mid-session and the capture goes black. The ZV-1 runs warm in 4K; High buys real runtime.

If it is still missing after all that

Work down in this order. The cable — the ZV-1's port is micro-HDMI (Type D), and a marginal cable can pass 1080p fine yet fail the EDID read that tells the camera it is talking to a 4K device. The port — move the Cam Link to a different Mac port and confirm it still enumerates. Menu recall — if the camera has a customized menu, check the Setup tab page by page rather than trusting recall. A settings reset is the blunt last resort.

Verify before touching OBS

Re-run the tool. You want 3840 x 2160 to appear under Cam Link 4K, and the format count to change from 2. If it does not, the camera is still sending 1080p and no OBS setting will change that. Reconnect the HDMI cable after any camera change — the Cam Link caches the handshake and keeps reporting stale modes.

./caps      # full mode list
./sig       # connection state + format count

What 4K costs you here

The Cam Link offers 4:2:2 chroma (yuvs) at 1080p but only 4:2:0 (420v) at 2160p, so the 4K path subsamples color more aggressively. At four times the pixel count it is still clearly the better image — but the trade is real, and it is the Cam Link imposing it, not the camera.

Signal flow

How the chain should be wired

Camera→ Cam Link 4K→ 2160p29.97 420v · USB bus 0x02
HDMI source→ Elgato HD60 X→ 2160p30 420v · USB bus 0x32
Mic→ Wave XLR→ Wave Link + filters→ Stream Mix→ into OBS
↳ Monitor Mix→ Headphones never touches OBS
OBS canvas→ HEVC hardware + PCM→ .mov master→ YouTube

The two capture devices already sit on separate USB controllers (location IDs 0x02… and 0x32…) — keep them there. Two simultaneous high-bandwidth uncompressed streams on one shared bus is where dropped frames come from.

Recording

Your current output config is the main quality bottleneck

Simple mode, VBitrate=6000, RecQuality=Small, downscaled to 1080p, H.264. That is roughly a sixteenth of the bitrate a 4K master wants, at a quarter of the pixels. Switch to Advanced.

Output mode
Advanced

Type / Format
Standard · hybrid MOV
You already use hybrid MOV. Keep it — fragmented, so a crash or power loss leaves a playable file, and it carries PCM audio and ProRes, which MP4 will not.

Runs on the M4's dedicated media engine — near-zero CPU, and much better quality per bit than H.264 at 4K.

Deliberately generous. YouTube's own recommendation for 4K SDR upload is 35–45 Mbps H.264; 100 Mbps HEVC gives the re-encoder a clean master with room to spare. About 45 GB/hour against your 842 GB free.

8-bit. Use main10 with color format P010 only if you deliberately want a 10-bit pipeline — it helps gradients but complicates editing.

Frequent keyframes make scrubbing and cutting in an editor far more responsive. Costs little at this bitrate.

If you edit before uploading

Consider Apple ProRes 422 instead of HEVC — the M4's media engine encodes it in hardware, and it is dramatically friendlier on an editing timeline (no long-GOP decoding). The cost is size: roughly 210 GB/hour at 4K30 versus 45 GB/hour for HEVC. Fine for a one-hour shoot on 842 GB free; plan storage if you shoot often.

The division of labor

Wave Link owns everything you hear and every filter applied. OBS owns only what gets written to disk — it takes Stream Mix as a finished signal and does not process or play it back. Keep OBS's own audio filters empty unless you find something Wave Link genuinely cannot do.

Verification

Checking what OBS is actually receiving

OBS 32's capture plugin does not log the negotiated format, and a properties dropdown set to "Preferred" will not tell you what it settled on. Three reliable methods, cheapest first:

  • Source size in the transform dialog. Select the source, press ⌘E. "Size" is the true incoming resolution — not the scaled box on your canvas. Fastest resolution check, tells you nothing about frame rate.
  • The capability tool below. Lists every mode each device is currently offering. Because these capture devices advertise modes based on the signal they are being fed, this doubles as a check on what your camera is sending.
  • The Stats dock (View → Docks → Stats). Shows composited output FPS and frames missed due to rendering lag — the place to confirm the whole pipeline is keeping up once you hit record.

The tool is built and sitting at caps in this session's scratchpad. Re-run it after any camera or cable change:

swiftc -O caps.swift -o caps && ./caps

It needs no camera permission — enumerating formats does not open a capture session — and no dependencies beyond the Swift toolchain you already have.

Loose ends

Two unrelated fixes worth doing

Input monitoring denied
System Settings → Privacy & Security → Input Monitoring
Your OBS log shows this permission denied. Global hotkeys will not fire while OBS is in the background. Enable OBS there — relevant if you drive anything from the keyboard alongside the Stream Deck.
The 2.5-minute launch hang
Fixed by naming the audio device
Setting Mic/Aux to Wave Link Stream Mix rather than Default takes the HD60 X out of OBS's startup path, which is what stalled launch earlier. If it ever recurs: sudo killall coreaudiod.
